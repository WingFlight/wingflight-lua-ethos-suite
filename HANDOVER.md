# Migration Handover — Wingflight Lua Suite Rebuild

**Status as of this commit**: mid-migration, on `master`, working directly (no branch), nothing committed before this point in the migration. Picking this up on another machine: `git pull`, read this file, then `AGENTS.md`'s "Wingflight Migration Notes" section (11) for the technical detail behind every decision below.

## What this migration is

`src/wfsuite/` was rebuilt wholesale from `rotorflight-lua-ethos-suite`'s `rfsuite-full-rewrite` branch (a from-scratch architectural rewrite of that project — no shared global namespace, flat `lib/msp_*.lua` codecs instead of the old `tasks/scheduler/msp/api/` factory pattern, `app/pages/*.lua` instead of `app/modules/`), then rebranded and re-aligned for wingflight (fixed-wing firmware) instead of rotorflight (helicopter firmware). Everything under `src/wfsuite/` should be treated as **unverified against wingflight-firmware until individually checked** — see AGENTS.md section 8 for why that matters (several fields silently misaligned in the first pass and would have corrupted PID data on save).

Sibling repos referenced throughout this work:
- `C:\GitHub\rotorflight-lua-ethos-suite` (branch `rfsuite-full-rewrite`) — the rewrite this base came from. Its `.vscode/scripts/deploy.py` had the same Unicode console-encoding bug as this repo's copy; already fixed there too (uncommitted in that repo).
- `C:\GitHub\wingflight-firmware` — the actual firmware source. **Every MSP wire-format claim in this codebase should be verified against `src/main/msp/msp.c` in that repo directly**, not assumed from field names or the old lua schema.

## Done

1. **Base replacement**: `src/wfsuite/` replaced with the rewrite's `src/rfsuite/` content, full mechanical rebrand (`rfsuite`→`wfsuite`, `RFSUITE`→`WFSUITE`, `Rotorflight`→`Wingflight`, GPL copyright headers correctly left alone). `bin/i18n`, `bin/package`, `bin/sound-generator` replaced with the rewrite's versions + rebranded; `bin/menu`, `bin/sensors`, `bin/translation-editor` (wingflight-only tooling) kept as-is.
2. **Widget/task registration keys** fixed to match wingflight's originals (persistent per-user storage keys — getting these wrong would reset every existing user's saved widget config): dashboard `wfsdh`, ActiveLook `wfalk`, background task `wf2bg`.
3. **Logo/branding assets restored from git history** (Phase 1's rebrand only touched text, not binary image content or stale filenames): `app/gfx/icon.png`, `widgets/dashboard/gfx/logo-dark.png`/`logo-light.png`, and the kevd theme's logo files (renamed `rfsuite-*.png` → `wfsuite-*.png` to match code that already referenced the new names).
4. **Heli-only systems removed** (governor, rescue, swashplate mixer, main/tail rotor PID pages, rates_type/cyclic/collective-axis UI) and **MSP wire schemas rebuilt against wingflight-firmware's actual `msp.c`** for `lib/msp_pid_profile.lua`, `lib/msp_pid_tuning.lua`, `lib/msp_rc_tuning.lua`, `lib/msp_mixer_input.lua` (also fixed a real S16-vs-U16 signedness bug in the last one). `lib/rate_curve_scale.lua` simplified since wingflight-firmware hardcodes a single rate-curve formula now (`applyWingflightRates()`) — the old 7-table picker is gone.
5. **Feature Flags RAM-saving system**: deliberately **not** ported. `main.lua`'s own header documents that the rewrite already tried lazy widget loading and reverted to eager loading after on-device testing showed it made RAM behavior worse, not better. Full reasoning in AGENTS.md §11.
6. **AGENTS.md rewritten**: it described the pre-rewrite architecture entirely (dead menu generator, dead `tasks/scheduler/msp/` paths). Now accurate, plus a "Wingflight Migration Notes" section (§11) with the porting backlog and known traps.
7. **A live-reported crash fixed**: `pids.lua` still built widgets for `roll_o`/`pitch_o`, which Phase 2a had already marked dead in `FIELD_META`.
8. **`alignment_visual.lua` rebuilt** as a low-poly fixed-wing aircraft (fuselage/wings/tail) — was still drawing a helicopter (rotor disc, tail boom, skids). The 3D rotation/projection engine is generic and untouched; only the point geometry changed. (No trace of a previously-built plane model was found anywhere — git history, stash, reflog, dangling commits, VS Code local history all checked. If it turns up on another machine, it's a straightforward swap back into `POINTS`/`draw()`.)
9. **Wingflight features ported** (Phase 2c):
   - **Mixer Config** (`app/pages/mixer_config.lua`, new) — wing roll/pitch/yaw gain+invert via `MSP_GET_MIXER_INPUT`/`MSP_SET_MIXER_INPUT`.
   - **Cross Axis Relax, Master Gain, FW TPA** — added to `app/pages/pid_controller.lua` (fields were already correctly decoded from the Phase 2a `msp_pid_profile.lua` rebuild, just needed UI).
   - **Arm Ready Wiggle** — `lib/msp_arming_config.lua` built from scratch (didn't exist at all in the rewrite base). Expanded past the old single "Ready" checkbox to all 4 triggers wingflight-firmware now supports (Ready/Armed/Error/Fatal, `src/main/pg/arming.h`'s `wiggle_e` enum) — **but the user asked to pull the UI back off `configuration.lua`; the codec stays, unused, ready for whichever page it should actually live on.**
   - **Auto Trim / Att Hold** — Att Hold + Auto Hover PID-tuning groups added to `app/pages/autolevel.lua`.
   - **Flight-mode audio announcement system** — built from scratch (didn't exist in the rewrite base at all): new `flight_mode` telemetry sensor (S.Port `0x5121`/CRSF `0x1201`) wired through `tasks/session.lua` → `tasks/audio_events.lua`'s `announceFlightMode()` (11-bit priority table: Failsafe/GPS Rescue/Passthrough/Manual/Auto Hover/Att Hold/Auto Trim/Horizon/Angle/Trainer/Alt Hold) → new Settings toggle. **13 spoken-phrase entries added to `bin/sound-generator/json/*.json` for all 12 locales, but the actual `.wav` files are not generated** — that needs Google TTS credentials the user has and will run themselves.

## Practical notes for resuming

- **Deploy/test loop**: `python .vscode/scripts/deploy.py --lang en --step i18n --step soundpack --step sensors` from the repo root mirrors `src/wfsuite/` into `simulators/X20PRO_EU@nightly26/scripts/wfsuite/` (resolves i18n tags, syncs audio, etc.) without touching real hardware. Run this after any change before trusting it.
- **Safety sweep** used throughout this migration to catch dangling references before they became live crashes:
  ```
  grep -rhoE 'loadfile\("[^"]+"\)' src/wfsuite --include=*.lua | sed -E 's/loadfile\("(.*)"\)/\1/' | sort -u
  ```
  then check each resolved path exists relative to `src/wfsuite/`. Do this after every batch of edits — it caught a real crash-causing bug (a `loadfile()` in `tasks/session.lua` pointing at a file deleted earlier in the same session) that static reading alone missed.
- **i18n editing pattern**: new keys need adding to **both** `src/wfsuite/i18n/*.json` (what actually ships) and `bin/i18n/json/*.json` (nominal source, currently drifted — see above) across all 12 locales, English with `needs_translation: false`, others with `needs_translation: true` and the English text as a placeholder. The two files use slightly different field ordering — check an existing entry in each before adding a new one, don't assume they match.
- No lua interpreter is available in this shell environment — every change in this migration was verified statically (loadfile sweeps, i18n resolution checks, `FIELD_META` cross-referencing, direct firmware source reading) and via the deploy pipeline, never by actually executing the lua. Actual execution (simulator or hardware) is the biggest verification gap — see Phase 4 above.
